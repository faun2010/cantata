# 作曲家姓名配置与 LLM 补充

作曲家的规范姓名以 IMSLP 人物页为依据，不能将其他网站的拼写直接当作新人物。程序自带 `context/composer-identities/taneyev.json`，例如 `Sergey Taneyev` 是规范名，`Sergei Taneyev` 是别名及英文维基条目名。曲库姓名解析、在线简介、头像身份校验共用此配置；原有内置姓名表作为未覆盖人物的后备。

## 文件与更新

用户扩展文件为应用配置目录下的 `composer-identities/taneyev.json`：Linux 通常为 `~/.config/cantata/composer-identities/taneyev.json`，其他平台使用 Qt 的 AppConfigLocation。虽然沿用 taneyev.json 名称，`people` 数组可以收录多位作曲家。首次通过核验的自动补充会创建此文件并包含内置记录；手工编辑时也可复制源码中的同名文件作为起点。

文件包含 `version: 1` 和 `people`。每个人至少包含 `canonical`、IMSLP `Category:姓,_名` 形式的 `imslp`、`aliases` 数组；可提供 `zh`、`wikipedia.en`、生卒日期、MusicBrainz ID 与 `sources`。

配置修改后在下一次姓名解析时重新读取，无需编译。损坏的 JSON 保留本进程最后一次有效配置；首次加载失败则仍可使用内置人物。不同人物的别名冲突返回歧义，不选择第一个。建议只录完整姓名，不将单姓作为唯一身份。

## 自动补充流程

使用现有 `translation.ini` 中启用的翻译 LLM、模型、代理及请求队列。未启用翻译时不会自动联网补充。

1. 打开艺术家信息、请求简介翻译，或艺术家头像下载失败时，尝试解析尚未配置的人物。
2. 专用提示词 `composer-identity-v1` 要求 LLM 只提出该作曲家的 IMSLP 人物分类，不能直接提交姓名别名或译名；不确定时返回空对象。
3. 程序通过 HTTPS 抓取 `imslp.org` 对应页面，验证页面标题、作曲家作品区及人物头部的完整姓名。不会从作品列表、正文里偶然提及的人物推断身份，也不会自动追随重定向到其他站点。
4. 从已验证页面提取规范名、完整别名、简体中文名及同一人物的维基链接。与其他配置人物或内置作曲家冲突时拒绝写入。
5. 用原子写入更新用户 JSON；损坏文件不会被自动覆盖，并发编辑被检测到时放弃本次写入。更新后自动重新加载当前艺术家信息，并为该人物重试失败头像。

同一名字十分钟内最多尝试一次；IMSLP 核验请求最多同时两个，超时十五秒。无效提案、网络故障或不能证实人物时保持已有配置，在日志中记录原因。

## 译名一致性

翻译提示词携带相关人物配置，要求采用 `zh` 的中文名。配置版本参与译文缓存键，更新后不会继续命中旧姓名配置下的译文；在途的旧配置译文也不会覆盖新结果。

艺术家简介中已收录的中文别名会统一到配置中的中文名。检测到不同已知别名，或应使用的中文名没有出现在中文译文中时，会触发 IMSLP 复核。无法判断身份的新译名不会凭 LLM 猜测加入配置。该机制减少已知姓名冲突，不能保证发现自然语言中的所有翻译错误。

IMSLP 不收录的人物、页面格式变化或名字未列在人物头部时，自动补充会保守拒绝。此流程只扩展作曲家，不将歌手或乐团自动登记为作曲家。

## 验证

`composeridentities_test` 检查姓名加载、热更新、错误文件保留、别名冲突及 IMSLP 头部解析。`composeridentityservice_test` 用模拟 LLM 和 IMSLP 响应验证完整写入流程、错误人物拒绝、内置姓名冲突、中文别名统一和关闭翻译时不请求网络。
